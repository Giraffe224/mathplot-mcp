# 连接稳定性与中文渲染问题诊断报告 — 2026-08-21

> 环境：Redmi (Android 16) / Termux / RikkaHub（master 分支，McpSessionRegistry 实现）/
> MathPlot MCP v1.4.1 / kotlin-sdk StreamableHttpClientTransport。
> 复现手段：adb force-stop 双端 + run-as com.termux 直执命令 + `adb forward` 直连 MCP 端口 +
> logcat 过滤 `McpSessionRegistry` 标签 + 服务器访问日志。

---

## 问题 1：中文渲染为方框（tofu）

**已复现，根因确定。**

- Termux matplotlib `fontManager.ttflist` 中只有 DejaVu / STIX / Computer Modern 系列，
  **无任何 CJK 字体**；`mathplot_mcp.py` 也没有任何字体配置。
- 调用 `plot_function(title="正弦函数图像：测试中文")` 时，matplotlib 对每个汉字告警
  `Glyph NNNN missing from font(s) DejaVu Sans`，图上渲染为 □□□。
- 好消息：手机系统字体 `/system/fonts/NotoSansCJK-Regular.ttc`（32MB，全局可读）可被
  matplotlib 3.11 直接 `addfont()` 加载，实测成功注册 `Noto Sans CJK SC/TC/JP/KR/HK`
  五个字体面——只是代码没写加载逻辑。

## 问题 2：RikkaHub 先于 MCP 启动时无法连接

**已复现（坏顺序：RikkaHub 先、Termux 后）。**

实测时序（logcat `McpSessionRegistry`）：

1. RikkaHub 启动即对 `http://127.0.0.1:8000/mcp` 发 initialize → `ECONNREFUSED`
   （20s 连接超时）→ 状态置 Error；
2. 随后启动 Termux + MCP 服务器，**等待 70 秒，RikkaHub 零次重试**
   （服务器日志无任何新请求）。

根因（三层叠加）：

| 层 | 事实 |
| --- | --- |
| 服务器（主因） | runit 服务目录 `~/var/service/mathplot-mcp/` 存在但带 `down` 文件——Termux 启动 / 手机重启后 MCP **永不自启**，需手动 `mathplot` |
| RikkaHub | `McpSessionRegistry.kt`：连接仅在「设置变更 / 手动同步 / callTool」三种时机触发；**启动失败后无定时重试**；只有连接成功过、之后 transport 断开才会走自动重连 |
| 交互 | 首连失败时若工具列表从未同步成功过，模型拿不到工具定义 → 连触发 callTool 兜底重连的机会都没有 |

## 问题 3：连接时好时坏 / 断后无法恢复

**已复现，且比预想严重：服务器一旦死亡超过约 30 秒，RikkaHub 永久卡死。**

实测：正常连接后 `pkill` 服务器 → ~28 秒后 RikkaHub 报
`Streamable HTTP error: Maximum reconnection attempts exceeded` → **恢复服务器后等 40 秒，
RikkaHub 零请求**，状态仍显示已连接，仅重启 RikkaHub 或改设置可救。

根因链（客户端 bug，但可从服务端绕过）：

1. Kotlin SDK `StreamableHttpClientTransport` 在 initialize 后对 `GET /mcp` 建常驻 SSE 流，
   流断开后 SDK 内部重连（指数退避，~3 次 / ~28 秒耗尽）；
2. 耗尽后 `_onError("Maximum reconnection attempts exceeded")`；
3. RikkaHub `isSseStreamGiveUpError()` **特意忽略**该错误（防 SSE 服务器无限重连风暴）；
4. 此时 `session.client` 仍非空 → 后续 `callTool` 因 `connectedConfig` 匹配而不走重连分支
   → **服务端怎么恢复都无济于事**。

「有时能连上有时不能」的随机感来源：服务器中断时长是否落在 SDK ~28 秒重连窗口内。

## 顺带发现的小问题

- 服务器前台运行时访问日志只打到终端，不落盘（本次排障只能依赖 logcat）；
- `SESSION_IDS` 只增不减（缓慢内存泄漏）；
- `DELETE /mcp`（会话终止）未处理，返回 404。

---

## 修复方案（2026-08-21 与用户确认）

- **A. 中文字体**：启动时 `addfont` 系统 Noto CJK + rcParams 回退列表（已验证可行）。
- **B. GET /mcp 改返回 405**：kotlin-sdk `isNonRetryableSseError()` 对 GET 的 405/404/JSON
  响应进入 "stream disabled / JSON-only 模式"，不报错不重连、transport 保持健康。
  本 MCP 全部工具均为请求-响应式，不需要服务器推送流。效果：
  服务器死亡 → 无 SSE 流断裂 → 不触发 RikkaHub 的 give-up 过滤 →
  下次 POST 失败走 RikkaHub 标准重连（5 次退避）；即便耗尽，callTool 的
  `connectedConfig==null` 兜底分支也能在下一条聊天消息时自愈（SSE 模式下永不发生）。
- **C. 服务器常驻方案：用户否决**——该机为日常用机，不做 runit 自启 / wake-lock /
  Termux:Boot / 禁用幽灵进程杀手。改为按需手动启动 + 依赖 B 的自愈能力；
  详细讨论见 CHANGELOG v1.5.0。
- **D. 健壮性小修**：访问日志统一落盘、SESSION_IDS 封顶、处理 DELETE、
  initialize 附 instructions。
